Onde Caçar

Calendário gratuito dos dias de caça nas zonas de caça municipais, construído a partir de centenas de PDFs publicados pelo ICNF.

  • Python
  • Playwright
  • IA com visão
Visitar ondecaçar.pt ↗

Antes

  • Informação dispersa em centenas de PDFs
  • Consulta zona a zona, lenta e pouco prática
  • Sem visão por concelho, distrito ou espécie
  • Candidatura a cada zona preenchida à mão

Depois

  • Um único calendário, gratuito e fácil de consultar
  • Pesquisa por concelho, distrito e espécie
  • Dados validados antes de serem publicados
  • Candidatura gerada diretamente no site

Como funciona

  1. 1

    Recolha

    Scraping automático do site do ICNF (Playwright), por distrito. Cada PDF novo é descarregado e a primeira página é convertida em imagem — o PDF é depois descartado, só a imagem fica em disco.

  2. 2

    Tratamento e Processamento

    A imagem é endireitada com base no ângulo da própria grelha da tabela. De seguida, os cruzamentos da grelha são detetados e cada célula é recortada e remontada numa imagem nova, sem sobreposições.

  3. 3

    Extração

    Um agente de IA com visão lê a grelha de recortes diretamente e devolve os dados estruturados — sem OCR e sem custo de API por imagem.

  4. 4

    Validação e Calendário

    Validação automática de inconsistências, seguida de revisão humana numa webapp própria. Só depois cada intervalo de datas é expandido nos dias da semana permitidos, feriados incluídos.

Obstáculos do projeto

OCR (Tesseract) célula a célula não aguentava a variedade real dos ~300 documentos.

O pipeline de OCR foi abandonado. Passou a montar-se uma grelha só com os recortes de cada célula, lida por um agente de IA com visão — que entende a tabela como imagem, não como texto solto.

Extrair ~300 documentos por API paga da Claude não escalava.

A chamada direta à API foi removida. O sistema passou a gerar apenas os prompts; a extração é feita por agentes Claude Code, lançados manualmente, sem custo de API por imagem.

Scans nunca perfeitamente direitos desalinhavam a deteção da tabela.

Passou a calcular-se o ângulo de rotação a partir da própria grelha da tabela e a endireitar a imagem antes de qualquer deteção de células.

Dados espalhados por tabelas paralelas, ligadas por caminho de ficheiro.

O esquema foi unificado numa única tabela, ligada por identificador numérico em vez de uma string de caminho — evitando problemas de barras invertidas e escaping.

Reservas "desaparecidas", puladas para sempre pelo pipeline sem explicação.

Uma versão antiga só gravava a imagem processada em certas condições, mas a base de dados guardava sempre o caminho. Passou a confirmar-se sempre a existência real do ficheiro em disco.

Confiar cegamente em dados extraídos por um agente de IA.

Nenhuma linha entra no calendário sem validação automática de inconsistências e revisão humana numa webapp própria, antes de ser marcada como pronta.
